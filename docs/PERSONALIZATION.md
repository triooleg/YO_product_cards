## Настройки

Settings → YO Product Cards → Product personalization:

- общий переключатель;
- отдельный переключатель каждой услуги;
- `size_adaptation_price` = 25 EUR;
- `matching_headpiece_price` = 15 EUR;
- `extra_rhinestones_price` = 10 EUR.

Цены хранятся в `yo_pce_settings`, проверяются как конечные неотрицательные числа и округляются до двух знаков. Значения других вкладок при сохранении сохраняются. Все услуги в каждой карточке изначально не выбраны. Общий переключатель по умолчанию включен; для отключения новой верстки выключить Product personalization.

## Карточка

Новые блоки создаются для карточек с ценой и измерениями либо заголовком `for height`. Заголовок/рост, фото и существующий Need help buying остаются на месте. SIZE использует те же `.yo-measure[data-cm]`: узлы перемещаются в четыре колонки, прежний переключатель переносится вправо. Исходные размеры костюма не заменяются скорректированными: корректировки показываются в popup и передаются отдельно как пожелания клиента.

Adaptation доступна при распознавании четырех подписанных положительных измерений Chest/Waist/Hips/Torso. Каждое значение может быть одним числом или диапазоном через дефис/тире. При неполных или неверных размерах Adaptation отключена; остальные доступные услуги работают. Названия можно явно указать через `data-measurement="chest|waist|hips|torso"`.

Popup предлагает только 0, −1, −2, −3, −4 cm для Chest/Waist/Hips. Torso (дуга) заблокирован: его корректировка всегда равна 0, включая снимок для Checkout. Применение уменьшает обе границы диапазона. Cancel/Escape не сохраняют черновик и возвращают прежнее состояние checkbox. Повторное открытие показывает примененные значения; снятие услуги сохраняет их до перезагрузки. Диалог имеет фокус, закрытие через Escape и прокрутку на узком экране. Tooltip услуг доступен при hover/focus.

Переключатель cm/in присутствует и в карточке, и в popup. В popup он конвертирует Original, Adjusted и отображаемые варианты уменьшений через общий форматтер/коэффициент существующего модуля. Внутренние значения уменьшений остаются целыми cm: выбор −0.8 в режиме IN соответствует −2 cm. Изменение единиц popup не меняет единицы карточки; начальное значение берется из карточки. Суффикс `in` возле размеров убран, единица обозначена в заголовках SIZE (IN), Measurements (IN), Original (IN), Reduce by (IN).

Верстка 1.1.1 оформлена по приложенному макету: светлая карточка, SIZE с иконкой, иконки трех услуг, цветная кнопка покупки, валюта справа и полноширинная помощь ниже. Иконки — локальные SVG (Lucide ISC и собственная рулетка); внешняя библиотека в браузере не требуется. Стили явно учитывают `.yo-manager-actions-host` и `.yo-manager-help-discount`: help остается в родительском контейнере покупки, чтобы observer Checkout не создавал кнопку повторно.

Формула:

```text
display_total_eur = base_price_eur − product_discount_eur + selected_addons_price_eur
370 − 50 + 25 + 15 = 360 EUR
```

Скидка не затрагивает услуги. Бейдж вынесен в верхний правый угол, старая цена остается перечеркнутой возле покупки. Валюта располагается справа от Buy. С версии 1.1.2 по уточнению владельца выбор валюты относится только к текущей карточке: ее цена, скидка и услуги пересчитываются, остальные карточки сохраняют свои валюты. Кэш курсов по-прежнему общий. Повторная инициализация и выбор услуг не сбрасывают валюту существующей карточки; новая DOM-карточка получает default_currency. API `currency` возвращает валюту соответствующей карточки. При недоступном курсе отображается EUR с обозначением EUR; число EUR не маркируется как USD. Округление отображаемой валюты до целого сохранено из предыдущей версии.

Шрифт значений SIZE уменьшен с 16 до 14 px, в узких блоках до 12 px. Диапазоны не переносятся; размер шрифта определяется контейнером, а не выбранной единицей. Высота блока при переключении cm/in остается прежней.

## Контракт с Checkout

Checkout в этом этапе не изменен и пока не добавляет услуги в заказ или оплату. Новый итог в карточке является предварительным отображением. Для запуска платных услуг в продажу требуется отдельная серверная интеграция Checkout.

Публичный API после инициализации:

```js
const selection = window.YOProductCardPersonalization.getState(cardElement);
// Также допустим product/feed ID или card_key:
const sameSelection = window.YOProductCardPersonalization.getState('product-feed-slug');
```

Возвращается независимый снимок либо null; изменение снимка не меняет состояние карточки. Схема:

```json
{
  "schema_version": 1,
  "product_id": "product-feed-slug",
  "card_key": "product:product-feed-slug",
  "identity_source": "product",
  "currency": "EUR",
  "base_price_eur": 370,
  "product_discount_eur": 50,
  "discounted_base_price_eur": 320,
  "addons_price_eur": 40,
  "display_total_eur": 360,
  "addons": {
    "size_adaptation": {"enabled": true, "price_eur": 25, "adjustments": {"chest": -2, "waist": -3, "hips": 0, "torso": 0}},
    "matching_headpiece": {"enabled": true, "price_eur": 15},
    "extra_rhinestones": {"enabled": false, "price_eur": 10}
  }
}
```

События на карточке с `bubbles: true`: `yo:pce:addons-changed` после изменения состояния и `yo:pce:buy` при клике покупки. `detail` содержит снимок выше. Buy-событие не отменяет клик и не открывает checkout самостоятельно. Для гарантированного чтения перед уже зарегистрированным capture-обработчиком Checkout будущая интеграция должна вызвать `getState(card)` непосредственно внутри обработчика Checkout, а не зависеть от порядка регистрации событий.

`data-eur` у цены покупки остается дисконтированной базовой ценой товара, потому что текущий Checkout читает этот атрибут. `data-yo-display-eur` содержит отображаемый итог с услугами; это не доверенное значение для сервера. `data-cm` содержит исходные размеры.

Приоритет идентификации: `data-product-id`, `data-feed-id`, `id`. Без ID используется локальный ключ по заголовку/исходной цене/размерам; product_id = null. Это временный ключ страницы, не серверный SKU. Позднее совпадение с фидом переносит выбранные услуги на feed ID. Полная перерисовка того же товара восстанавливает выбор по ключу; дубликаты товара на странице представляют одну товарную конфигурацию. Неоднозначные товары с одинаковыми заголовком/ценой/размерами нужно обеспечить явным product ID.

Будущий сервер Checkout обязан заново определить цены услуг, доступность модели, скидку, предел уменьшений и рассчитанный итог. Данные браузера могут быть подменены. Ни платежные запросы, ни order API в этот плагин не добавлены.

## DOM и проверки

Инициализация идемпотентна. Один observer следит за добавленными элементами и атрибутами идентификации/измерений. На время собственных структурных изменений он отключен; обработчики событий делегированы и зарегистрированы один раз. Диалог создается один на страницу. API `initialize()` доступен для явного вызова после изменений темы.

```powershell
npm ci
npx playwright install chromium
npm test
php tests/settings.test.php
node tests/frontend-sale-button-labels.test.js
node --check yoleotard-product-card-enhancer/assets/js/frontend.js
node --check yoleotard-product-card-enhancer/assets/js/personalization.js
php -l yoleotard-product-card-enhancer/yoleotard-product-card-enhancer.php
python tools/package-plugin.py
git diff --check
```

Playwright проверяет формулы normal/sale/каждая услуга/все/снятие, −1…−4 cm и запрет увеличения, повторное открытие и отмену, EUR/USD, повторную инициализацию и DOM-render, неполные размеры, отсутствие и позднее появление feed ID, метаданные покупки и замену цены сторонним скриптом, ошибку курсов, master switch. Размеры viewport: 1440, 820, 375, 320 px; диалог помещается и страница не имеет горизонтальной прокрутки. Снимки находятся в локальном test-results/.

Дополнительно проверяются заблокированный Torso и переключатель popup. Тесты геометрии запускают реальный snapshot manager-скрипта и CSS из соседнего Checkout, включая его MutationObserver и меню помощи. Снимки источников зафиксированы в `tests/fixtures/`; production Checkout не изменяется.

Для проверки действующего YOOtheme без изменения сайта: `node tools/preview-live-design.js`. Скрипт загружает публичную страницу с локальными JS/CSS в своем Chromium, блокирует не-GET запросы и проверяет геометрию на четырех ширинах. Это проверка представления, не установка плагина и не проверка заказа.

Установка на WordPress и полноценный end-to-end заказ с услугами этими локальными тестами не подтверждены. Перед установкой на основной сайт проверить на staging взаимодействие UIkit/lightbox, действующий Checkout, настройки WordPress и актуальный XML-фид.
